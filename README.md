# Легенды подземелий — карточки персонажей

Веб-приложение на восемь карточек. Каждый игрок открывает одну ссылку, один раз выбирает своего персонажа, дальше телефон помнит его сам.

## Что уже работает

- **Выбор персонажа** при первом открытии, потом сразу его карточка. Сменить — в меню наверху.
- **Здоровье** в виде `13 / 20`. Нажатие открывает окно с уроном и лечением, быстрые кнопки 1, 5, 10 и поле для любого числа. На половине здоровья плашка желтеет, на нуле краснеет и пишет «Выведен из строя».
- **Заряды способностей** — квадратики. Нажал: заряд потрачен. Нажал на потраченный: вернулся. Когда кончились, способность бледнеет.
- **Ультимейт** знает цену. Монет не хватает — кнопка гаснет и говорит, сколько нужно. Хватает — списывает.
- **Порча и монеты** в нижней панели, общие на команду, кнопками плюс и минус.
- **Новый бой** возвращает заряды «за бой» и снимает выбор на этот бой. **Новый день** возвращает всё и лечит до максимума.
- **Автосохранение.** Закрыл вкладку, выключил телефон — состояние на месте.
- **Печать всех восьми карточек** на A4 — из меню. Макет тот же, что был, интерактивность из печати убрана.

### Автоматика по классам

| Персонаж | Что считается само |
|---|---|
| Жрец императора | Молитвы гаснут при порче 1, 2 и 3. Порчу почистили — вернулись |
| Кающийся еретик | Все шесть характеристик растут на 1 за каждое очко порчи. Апофеоз обнуляет порчу |
| Неофит астартес | С Проклятым основанием и порчей на столе входящий урон делится пополам |
| Сестра милитант | Каждые 5 полученного урона дают команде монету |
| Псионик | Кнопка крит-провала списывает 3 монеты и предупреждает, если платить нечем |

## Как запустить

Просто открыть `index.html` в браузере уже работает, но телефон так не установишь и файл придётся раскидывать по устройствам вручную. Поэтому лучше положить папку на бесплатный хостинг — получится одна ссылка на всех.

**GitHub Pages.** Создать репозиторий, загрузить все файлы в корень, в настройках Pages выбрать ветку `main` и папку `/root`. Через минуту адрес вида `https://имя.github.io/репозиторий/`.

**Cloudflare Pages.** Создать проект, выбрать «Direct Upload», перетащить папку. Адрес выдаётся сразу.

Любой вариант даёт https, а он нужен для установки на телефон.

## Установка на телефон

Открыть ссылку в браузере → меню браузера → «Добавить на главный экран». Появится иконка, приложение откроется без адресной строки и будет работать без интернета.

## Как править текст

Текст персонажей лежит в `build.py`, в списке `CHARS`. Поправил — запустил:

```
python3 build.py
```

`index.html` пересоберётся. Руками разметку править не нужно, иначе следующая сборка затрёт правки.

После обновления файлов на хостинге подними номер версии в `sw.js` (`const V = 'legendy-v1'` → `legendy-v2`), иначе телефоны продолжат показывать старую версию из кэша.

## Что дальше

Порча и монеты сейчас вводятся руками: мастер объявляет число, каждый ставит его у себя. Автоматика от этого работает полноценно, но телефоны между собой не связаны.

Синхронизация делается заменой одного объекта `Team` в начале `app.js` — там намеренно собраны все чтения и записи командных счётчиков. Сетевой вариант: комната с кодом на Cloudflare Workers, порядка сотни строк на сервере. Остальной код трогать не придётся.

## Версия с Firebase Authentication

В этой сборке добавлены:

- регистрация по электронной почте и паролю;
- вход в существующий аккаунт;
- сохранение входа после закрытия браузера;
- восстановление пароля по электронной почте;
- выход из аккаунта через меню карточки;
- отдельное локальное сохранение карточки для каждого Firebase-пользователя на одном устройстве.

Перед публикацией в Firebase Console должно быть включено:

1. `Authentication → Sign-in method → Email/Password → Enabled`;
2. `Authentication → Settings → Authorized domains` — добавлен домен GitHub Pages, например `kithoone.github.io`.

Загрузите в корень GitHub-репозитория все файлы сборки, особенно:

- `auth.js`;
- `firebase-config.js`;
- обновлённые `app.js`, `app.css`, `index.html`, `build.py`, `sw.js`.

После загрузки дождитесь новой публикации GitHub Pages и откройте сайт с параметром версии, например `?v=auth1`.

### Ограничение текущего этапа

Firebase сейчас отвечает только за учётную запись. Здоровье, заряды, выборы, порча и монеты пока сохраняются в браузере отдельно для каждого пользователя. Они ещё не синхронизируются между телефоном и компьютером. Для этого следующим этапом подключается Cloud Firestore.


## Cloud Firestore — постоянный персонаж

В этой версии один документ `characters/{firebaseUid}` хранит:

- имя и архетип персонажа;
- текущее здоровье;
- потраченные заряды;
- выбранные пакты, основания, гимны и улучшения;
- броню, оружие, урон и список предметов;
- локальные порчу и монеты (до появления общей команды).

### Включение

1. Firebase Console → Build → Firestore Database → Create database.
2. Выберите Standard edition, Production mode и ближайший регион.
3. Откройте вкладку Rules.
4. Скопируйте туда содержимое `firestore.rules` и нажмите Publish.
5. Загрузите все файлы этой папки в корень GitHub-репозитория.

Командная синхронизация между разными аккаунтами ещё не включена. Сейчас облако синхронизирует одного персонажа одного аккаунта между его устройствами.
